# 2.0.1-debug7 — 通知与展开流体云修复候选

## 代码层发现与处理

- 展开场景使用新捕获 epoch，但旧的区域快照优先返回，导致已经就绪的全屏新帧被挡住。现按消费者 epoch 筛选区域和全屏快照；过期全屏帧主动排队更新，其他消费者仍可保留有效帧。
- 流体云插件的原生挂载在 base attach 之后才配置背景，初次 layout 前宽高还可能是零。背景补挂与捕获需求建立移到原生挂载后，必要时等首次有效布局。
- 抓屏排除策略仅在通知中心真正可见时要求其可用 Surface，避免过期的展开状态拦截新通知／流体云请求。普通页面没有可见玻璃消费者时仍不抓屏；锁屏壁纸来源保持独立。
- 原生背景可以注册独立合成器模糊区域，省略其 draw 不足以停用上次的模糊。流体云和轻打扰横幅仅在本帧玻璃绘制成功后将原生区域 alpha 归零；缺源或禁用时恢复逻辑 alpha，不把通知的临时背景参数永久替换。顶部通知仍保留原生绘制分支、裁剪和进场 alpha。
- 原展开／横幅直接 Canvas 材质路径接入现有受需求限制的 GPU 背景准备，与通知中心采用相同准备方式，不引入 CPU 模糊或全局持续抓屏。
- 通知、展开卡片共用包装器的原生轮廓／状态／level／hotspot／可见性等回调均在绘制 try-catch 外执行，现单独隔离异常；轮廓查询不改动原生 RenderNode bounds；增加 draw 重入防护并确保退出释放。
