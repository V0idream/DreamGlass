# 2.0.1-debug5 本地候选验证

2026-11-10。针对用户报告的“展开流体云黑底”和“顶部通知只有模糊”。本轮未操作实体设备、未安装、未重启，未申请 Shell Root，也未上传 GitHub。

## 改动依据

- 本地 COS17 插件的 CardBackgroundView 覆写 draw，继承空的 View.onDraw。原生背景使用强模糊与深色混色。本次在背景 Drawable 出口绘制共同 GPU 玻璃；原生内容与进出场透明度仍保留。
- 通知背景的原生 draw 会依据主题、BP 模式与 ViewBlurProxy 选择不同 Drawable。只登记映射不保证玻璃最终执行。本次替换实际选中的背景，同时保持“选中背景是否等于原参数”的原生分支关系，不替换整个通知 draw，也不重复应用展开期间的裁剪。
- 轻打扰横幅属于基本通知玻璃，不再依赖展开流体云的会员开关。
- 流体云和横幅首现后要求新场景帧；缓存按帧代际交接，不清空其他消费者的有效帧。采集继续受可见宿主、需求、熄屏及锁屏规则约束。
- 原生背景回退在 GPU 透明度图层之外绘制，避免透明度／颜色过滤叠加两次；真正替换 View.background 的宿主转发原背景重绘、调度和可见状态。

## 验证及边界

- 334 项 JVM 单元测试，0 失败／错误／跳过：包含帧代际交接、嵌套通知绘制作用域和异常恢复。
- Debug 构建、Release Lint 及升级签名检查见 audit.json。
- 15 项本地原生源码／接入契约检查见 native-contract.json。它们是静态接入检查，不是实际厂商绘制证据。
- 扩充了 MenuBackgroundProbeActivity 中的半透明原生回退及 callback 转发断言。本轮仅编译，未执行 Android GPU 探针，不能作为 GPU 实测通过。
- Debug Lint 的 generateDebugAndroidTestLintModel 遇到工具 NPE；使用 Release Lint 完成静态分析。未隐藏该失败。
- 真机玻璃画面、通知入场／展开动画、实际功耗尚未验收。安装后必须让 SystemUI 重新加载，才能测试本轮代码。

未加入系统 APK、厂商反编译源码、私人截图或日志。未更换 GPU 模糊方案，也未添加普通页面切换时的常驻抓屏。
