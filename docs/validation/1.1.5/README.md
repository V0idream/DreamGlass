# DreamGlass 1.1.5 验证

最终源码包含经典／新版光学切换、音乐卡片几何修正、统一场景模糊、主题兼容与倾斜提交补强。下方保留 debug1–debug6 的历史调查记录；历史“尚未发布”等描述仅针对当时的候选，不代表最终版本状态。

## 最终验证与边界

148 项 JVM 回归通过。媒体注册沿实际背景 View 的父链识别卡片，保留当帧 Drawable 尺寸和采样原点，局部 Canvas 裁剪不再改变玻璃形状；负滚动坐标不再当作对称扩张。原生控件布局、触摸区域与系统裁剪不变。几何登记对可变 Rect 创建快照。

“新版渲染方案”默认关闭，使用 1.0.7 光学曲线；开启使用 1.1.4 紧凑镜片。开关直接控制共享 AGSL、桌面和应用材质，预览立即更新，系统组件重绘后更新。参数、组件覆盖与 IOS风预设不被重置。锁屏主题的独立字形材质不属于这一共享曲线切换。

窗口仅保存由已匹配的目标回调产生的透视；精确记录 native Transaction，合并后迁移至接收方，在真正 apply 前重写，防止后续仿射写入覆盖。记录使用弱引用、有数量与 240ms 期限，关闭及过期清理；不改变无关事务。通知倾斜在原生动画中段达到设置峰值，端点恢复，不在通知不可见时耗尽角度。

实体手机最后测试的是 debug5：已确认桌面菜单 0% 后图标／壁纸清晰；倾斜提交与可见行属性命中，但录屏没有足够明确的透视，仍未通过视觉验收。正式包已通过普通 ADB 覆盖安装并核对安装文件哈希，配置保留；没有重启手机上的宿主或做最终视觉验收。没有测量功耗或长期稳定性。模拟器合成图不等于厂商实际渲染。

## 锁屏主题与按钮

从已提取的 ClockBase 与系统框架中确认，`MyCustomizedTextView.applyRenderEffectInternal` 会调用 `OplusAsyncAnimatorUtils.setRenderEffect`，后者直接写原生 RenderNode，绕过 `View.setRenderEffect`。新增该入口的组合、原生效果保存与同路恢复，针对插件调用方取消内联；不更换主题、不改字形画笔、不处理 AOD。

`OplusLaunchableImageView` 的原生材质控制器会在系统材质接管时把旧背景 Drawable 的 alpha 清零。原适配据此跳过绘制，属于错误的可见性判断。改为跟随按钮 imageAlpha，并继续保留 View/父层透明度及启动变形。GPU 探针现在真实模拟旧背景 alpha=0，并验证玻璃仍绘制、图标保留、imageAlpha=0 隐藏及关闭后还原。

这些入口问题有代码证据；用户所用主题的最终时钟外观仍未解决；相机按钮已在 debug1 真机确认可见。

### debug2：实际字形绘制出口

真机 debug1 中，独立 GPU 字形对照能输出玻璃，而锁屏最终数字仍偏平。新增 `KeyguardGlyphDraw`：只针对已核对的 MyCustomizedTextView 原生 onDraw，在同一次绘制内执行一次原厂字形指令，再由私有 RenderNode 合成玻璃；外层 View 继续保留原生过渡效果。没有重建字体、额外屏幕捕获、像素回读、CPU 模糊或循环任务。几何与字体更新随原生绘制，释放时强制重录原生显示列表，防止关闭后留下空白缓存。

新 GPU 探针直接测试生产节点渲染器：字形透明度最大差值 0、3158 个内部像素使用玻璃、88→11 更新时 4392 个遮罩像素改变、关闭材质后还原差值 0；每帧原生绘制调用一次，字体与返回值保留。随后 debug2 真机记录确认 onDraw Hook 实际命中；最终锁屏截图仍偏平，因此不据此宣称时钟效果已完成。

### debug3：最后一级主题材质合成

继续核对当前设备主题组件后，确认数字与日期通过独立父层挂载最终原生玻璃／上色效果。仅对字形叶节点处理，仍会被后执行的父层材质重新上色。新增 `KeyguardNativeMounts`，从主题明确返回的时钟／日期挂载列表与效果映射中登记对应透明容器；不凭全屏容器名称扩大作用域。

将 DreamGlass 材质放在该挂载点原生效果之外；移除同一子树已有的字形附件，避免重复滤镜。原生遮罩、淡入淡出与深度遮挡继续参与合成，关闭时恢复最近一次原生效果。插件可能使用独立包 Context，因此用宿主进程判断，不按插件 Context 的包名错误排除。没有新增壁纸抓取、CPU 模糊、计时循环或依赖；未复制原厂实现及 shader。

GPU 回归增加了模拟原生父层重新上色的对照：旧顺序下子层玻璃被覆盖（与原色差值 0）；最终父层合成有 3044 个内部像素保留玻璃，原生透明度最大差值 0，恢复差值 0。已查看两幅合成图；这些证据验证合成顺序，不能证明具体 COS17 主题 Hook 已命中或最终外观已解决。相机原生分层回归仍通过。

## 通知菜单与统一背景模糊

COUI 菜单支持四参数 show，主题材质控制器在 show 之后仍可替换背景。接入实现方法并保留后续主题更新的原背景，菜单关闭时还原。新增实际绘制与主题重置诊断，避免把“注册成功”当作生效证据。

“采样与性能”页新增自定义展开页面背景模糊，默认关闭；力度 0–100%，开启后默认 30%。覆盖已核对的通知菜单 BlurUtils、桌面深度背景、桌面弹出层 GPU 滤波、负一屏背景接口及作用域内可匹配的 COUI 背景构建器。控制中心现有独立设置保持原用途。

只缩放原生请求，保留原生动画进度和淡出归零；不对已改写的字段反复相乘。桌面弹出层从原图经过现有 OEM GPU 滤波，定制结果不写进系统默认壁纸模糊缓存，避免下一次设置被缓存吞掉。没有新增 CPU 模糊或常驻捕获任务。100% 使用系统缓存与原值；修改后重新展开相关页面。

模拟器已检查开关、0/100 滑杆端点和返回路径。模拟器未安装 LSPosed，框架写入按既有逻辑排队，未声称验证真实框架配置持久化及系统 Hook。

## 应用动画倾斜

定位到 RectTransformHelper 的原生矩阵链及轻动画 AppLaunchAnimUtil$getLightWindowAnimation$1.b/onUpdate，最终通过 xi.q$b.i(Matrix)/j(float[]) 提交。旧适配丢弃非主线程帧，并未取消已核对调用方对小方法的内联。新增动画线程处理、线程安全状态、每帧独立矩阵及调用方去内联，保留原生缩放、位置和清理。

GPU 投影与通知变形恢复探针通过；模拟器没有 OEM SurfaceControl 4×4 通道，因此真实窗口是否出现倾斜仍需设备验证。诊断仅记录“提交入口已调用”，不会冒充可见效果验证。

### debug4：逐目标窗口矩阵与真实通知动画阶段

COS17 标准路径定位到 `RectTransformHelper.a → gi.c.g → ma.r0.run → xi.q$b.i(Matrix)`，轻动画定位到 `onUpdate → a7.a.run → b(...) → xi.q$b.i(Matrix)`。逐目标回调使用动画线程本地作用域，在最后一次原生仿射写入后只提交一次倾斜，避免中途注入被后续写入覆盖、共用事务串入其他目标或依赖固定 40 ms 猜测。轻动画使用原生裁剪后的局部坐标。核对底层公开 OEM 4×4 桥接并保留事务提交诊断；接口异常时回退原生。结束、打断与关闭仍有有界复位。

通知从 `performAddAnimation` 的排队阶段改接 `onAppearAnimationStarted`，并读取原生出现进度；横幅从真正的 `animateTo` 弹簧起点跟随位置进度。可见前的排队不再消耗固定 450 ms 特效，未显示的等待和异常动画均有超时上限。结束／脱离时清理，并保留后来接管的原生属性。增加可见行变换诊断，区别于仅注册入口。没有改写通知平移和业务回调。

### debug4：弹出桌面图标残余模糊

截图所示的不一致来自独立通道：原生桌面壁纸走 Bitmap GPU 路径，而图标／工作区截图走 HardwareBuffer GPU 路径，后者直接设置原生固定半径，绕过此前改写的高层 Bitmap 方法。改接这两路实际共有的 GPU 参数入口，仅在桌面弹出背景请求内缩放一次。0% 同时取消壁纸和图标层模糊，100% 使用原生力度；不再在高层重复相乘。低强度请求继续绕过已模糊壁纸缓存，定制结果不污染原生缓存。没有新增截图或 CPU 图像处理。

上述 Hook 契约与提取的当前版本组件逐项核对；模拟器能验证作用域隔离、变换、延迟可见、原生进度和复位，不能代替真实 OEM 4×4 通道、通知 Hook 及菜单图标清晰度的最终验证。

### debug4 真机结果与 debug5 原生矩阵布局修正

debug4 真机：两个宿主确认加载新包；0% 设置下，长按桌面图标的实际菜单后方图标与壁纸均清晰，菜单自身玻璃保留。通知原生开始回调与可见行变换已命中，当前角度为 3°，但未将其标为明显透视已验证。窗口中段 4×4 事务已提交，录屏未看到足够明确的透视，仍按未通过处理。测试通知已删除，没有改动配置。检测到前台切至相册后停止 UI 操作。

继续检查当前设备的原生调用链，确认 JNI 原样复制 Java 数组进入 `android::details::TMat44<float>`，客户端事务继续原样传递，而模块原先提交的是行优先数组。此前 GPU 探针直接按行读取数学矩阵，因此漏掉 ABI 错配。`nativeProjection` 现在将每帧自有数组原地转换为列优先，再交给 OEM 通道；单位矩阵和复位保持原义，没有新增采样、线程或图像处理。

新增回归按原生列优先方式读取真实提交数组，检查枢轴不漂移、上下边透视宽度不同、最大参数下四角仍位于投影平面前、端点／无效输入恢复单位矩阵。GPU 夹具也改为解码该原生数组，避免再次只验证未提交的数学表示。debug5 模拟器测试与合成图通过，尚待真机确认。

原生布局参考：[Android TMat44 定义](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/main/libs/math/include/math/mat4.h)。设备原生库、逆向分析及私人录屏只保存在本地工作目录，没有收入公开源码。
