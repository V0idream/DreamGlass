# 系统应用与通知菜单：1.1.8-debug3 候选

本轮先完成上游渲染区域调试功能并将 debug2 覆盖安装到手机，然后继续分析直接从手机提取的三个 APK。APK、反编译文件、手机日志与屏幕内容均留在仓库之外，未随源码分发。

| 应用 | 核对版本 | 本轮针对性处理 |
| --- | --- | --- |
| 计算器 | 17.2.16 | 识别 `FrameButton` 背景宿主及其 `COUIButton` 子控件；材质在父容器挂载一次，避免父子重复滤波。成功挂载后，子控件停止绘制原生不透明底和渐变位图，文字、图标及输入仍由原生绘制。 |
| 相册 | 17.10.41 | 识别 `BlurButtonWrapperView` 的真实按钮宿主与材质代理。保留原生子控件绘制，挂载成功后抑制重叠的原生底色与材质装饰。 |
| 负一屏 | 17.14.60 | 从当前 APK 的原生圆角背景 Drawable 发现卡片，不沿用 COS16 混淆类名。保留前景和原生圆角遮罩；已验证的卡片可以承载按钮行，整页根容器和工具栏仍排除。 |

三个应用没有此前通用纹理适配器依赖的那组 `posteffect.drawable.BaseDrawable` 接口，不能假定已有侧边栏路径可以通用。这轮为它们增加明确入口，继续使用同一 `AppGlassEffect`／`LiquidGlassShader` 和全局预设。没有引入 CPU 模糊、额外抓屏或整张前景的模糊。

原生填充抑制以已挂载的材质状态为条件；关闭功能、接口不匹配或未挂载时保留原生绘制。作用域只在对应应用进程，未改动此前认可的侧边栏材质。控件自绘中的临时状态在 finally 中还原，嵌套与跨线程绘制不能借用别的控件状态。

## 通知菜单

原来的菜单背景替换忽略 Drawable 的实际 bounds、padding 和 alpha，且绘制函数在缺少背景源时只返回空值，外层仍将其当作成功。这轮按背景实际边界登记采样区域与局部偏移，保留 padding、透明度、状态和裁剪；没有源或绘制失败时使用原背景，只有实际提交玻璃绘制后才记录成功阶段。

普通可复制背景在需要不同边界时独立绘制，避免修改共享状态；不可复制的原生背景保留当前几何，避免录制后回滚其活跃 RenderNode 导致错位。没有凭截图猜测去关闭整窗原生模糊或改写通知内容。

上述修正覆盖了代码中能够确认的问题，**尚未证明截图里的矩形异常已经消失**。仍需手机重新加载候选后，用青色渲染框定位菜单及各按钮的实际材质区域，再做可见对照。

## 验证与边界

- 175 项 JVM 测试通过，Debug／Release 构建通过，Lint 0 Error／0 Fatal／313 Warning。
- 对提取 APK 核对控件、父容器、填充与装饰方法契约；这是静态证据，不是宿主执行证明。
- 菜单 GPU 回读覆盖非零背景偏移、边界裁剪、缺源／异常回退、透明度、禁用状态和原生 padding。
- 新应用 Hook 尚未在手机完成执行与视觉验收。debug3 当前为候选，不能把编译或合成 GPU 测试写成“已适配成功”。

代码思路参考上游 `AppPageGlassMounter` 的“材质成功挂载后才抑制原生填充”，保留项目既有 GPLv3、上游与 Kyant 来源声明。debug2 的渲染框见 [调试说明](UPSTREAM_DEBUG_BOUNDS.md)；本轮没有宣称完成整个上游引擎合并。
