# DreamGlassforCOS17 开发记录

本轮完成 Preview 1 的本地开发与静态验证。最终的真机视觉、稳定性和性能验收仍未完成。

## 架构

- 产品层：`ui/DreamActivity.kt` 提供概览、材质实验室、运行诊断三个页面。使用原生 Android View、原创配色与矢量图标。三种材质预设复用真实 AGSL 预览，预览不等于系统截图。
- 高级控制：`ui/SettingsActivity.kt` 保留原有材质、采样、配置导入导出、桌面、文字、遮罩等设置。首页通过分类参数直达对应页面。
- 配置：所有有系统效果的写入先要求 LibXposed 框架服务就绪，再提交到 `liquid_glass_config`。本地 XML 只用于原设置的缓存，不当作跨进程成功证据。框架断连时禁止首页总开关写入。
- 能力识别：`hook/Cos17Contract.kt` 以真实类、字段类型和静态方法签名识别桌面内联绘制结构，避免版本读取时机未知导致误判。不通过返回固定成功值伪造兼容。
- 宿主适配：`entry/XposedEntry.kt` 只进入 SystemUI、Launcher 两个作用域。SystemUI 保留原来的绘制接入，Launcher 修正混淆字段与准备阶段。
- 图形：继续使用原项目的 AGSL、背景获取、对象池、场景过滤与参数系统。没有新写整套折射算法，也没有注入 system_server。
- 诊断：`diagnostics/RuntimeDiagnostics.kt` 每个宿主每个阶段只发布一次，存 PID、时间、版本及阶段文本；绘制线程不执行 Binder 或文件写入。实际后台提交失败不影响宿主。记录是历史事件，不是常驻心跳。

## 关键修改及原因

1. **桌面反射字段**：上游对部分成员使用了反编译器的展示别名。用户 APK 的 DEX 明确为 `f:Paint`、`h:RenderNode`、`i:Path`、`a:boolean`、`M:Paint`、`F:int`、`w:boolean`。现使用真实名称并在关键访问前核查类型。
2. **绘制生命周期**：静态入口 `com.oplus.posteffect.drawable.b.a(d)` 原本调用宿主准备方法并更新脏标记。现在先执行原实现，再使用已准备的几何录制玻璃；录制异常尝试重建原生内容，以线程内重入保护防止递归。
3. **早期版本读取**：Application 尚未就绪时版本可能未知。增加结构核验，未知值不固化为不支持。
4. **无效扩展**：所给桌面包没有 `ZuyqaWindowTilt` 或 `ZuyqaAnimationTuning`。不对它们制造成功状态；旧版弹簧和这条倾斜路径对该版本不可用，系统动画保留。
5. **身份隔离**：安装包 ID 改为 `com.dreamglass.cos17`，日志 Provider authority 与调用方允许名单同步调整。内部代码命名空间仍保留原名，体现来源并降低不必要重命名风险。
6. **实际 API 范围**：最低 SDK 提升至 33，以符合 RuntimeShader 等接口真实要求；不再声称在 Android 8 上可运行。
7. **权限**：壁纸代码在宿主进程执行，两个用户 APK 的 Manifest 均声明 READ_WALLPAPER_INTERNAL；新增宿主授权检查，失败回退。仅在这两个具体函数标注宿主权限语义，未给模块索要系统权限，未全局关闭 Lint。
8. **默认与恢复**：总开关仍默认关；保留系统模糊默认开、持续抓屏默认关。玻璃暂停独立于总开关，完全撤销 Hook 需目标进程重启。
9. **UI 资源**：注销配置页服务监听，预览离开窗口后停止续帧并释放引用，避免反复进入设置保留 Activity 或位图。
10. **发行身份**：关闭上游自动更新调用，移除模块 INTERNET 权限，避免向新产品用户推荐安装参考项目的 APK。保留全部合法来源声明。

## 后续按阶段验证

1. 在目标设备先验证安装、设置和框架识别，不启用 SystemUI。
2. 验证 Launcher 文件夹及 Dock、横竖屏、壁纸切换、暂停恢复和日志阶段。
3. 再验证 SystemUI 通知、控制中心、媒体、滑块、场景过滤、截图排除层及实际画面。
4. 测量 CPU/GPU、刷新次数、内存增长和长时间稳定性。
5. 在有真实调用链和材料后恢复可选流体云、锁屏和动画分支。

这些阶段没有提前宣称通过。已交付的是可编译、经过静态验证的第一版开发预览。
